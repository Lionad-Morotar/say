一页结论

现成 drop-in 存在但都不合格（sag 要付费云 key；gensay 仅 2★ 且无克隆路径），因此走你的第三优先「套壳自建」：Node 薄壳 say（PATH shadow，接口子集 + 未支持参数透传），底座为 sherpa-onnx 单宿主（Kokoro 英文 A 级通用嗓 + ZipVoice 零样本克隆 出芙莉莲 / D.Va / Lucy 角色嗓），失败自动回退 /usr/bin/say。英语为主，中文同嗓直读、不达标走通用预设。全部延迟数据待 s-bench 本机实测，默认引擎与默认角色由「跑分 + 你的试听」裁决。

高风险决策台账（需你 review，可推翻）

HR1 · 跳过「现成 CLI」次优路线，选择套壳自建

现成答案 gensay（say 接口全复刻 + daemon + 断网回退）仅 2★ 零社区验证，本地嗓需 ~2GB PyTorch，克隆能力未验证（其 chatterbox provider 为克隆向模型，但是否暴露参考音频接口未验）；sag 体验最顺但绑定 ElevenLabs 付费云，违反「离线永远可用」下限。自建的是薄壳（依赖面 = sherpa 宿主 + afplay），gensay 的接口复刻 / daemon / 回退设计被吸收为规格参照而非依赖。

推翻方式：回复「先试 gensay」→ s-bench 加测 chatterbox 克隆路径即可翻转。

HR2 · PATH shadow 全局劫持 say

命中你的首选「接口完全一致 alias」且 CLAUDE.md 零改动，ZCode / Codex 等所有 runtime 自动受益；代价是本机一切 say 调用方都改道。缓解：未支持参数原样透传 /usr/bin/say，任何失败自动回退系统音色。

推翻方式：回复「用独立命令名」→ 退路为 sayn + CLAUDE.md 改一行。
