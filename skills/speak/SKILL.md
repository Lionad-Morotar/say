# speak：通过 say 与用户实时语音交流

语音是交付主体，文字只做辅助。默认值与播放纪律来自实测（103 嗓全量试听、多段串联验证）。

## 要求

- 文字输出克制：语音播完后只留两三句中文简释，不复述、不堆正文
- 播放永远串行：叠声是本技能最严重的体验事故
- 用户全局约定（CLAUDE.md）优先于本技能

## 意图路由

- 带 `<内容>` 参数：直接按「交流模式」把内容说出来，收尾简释
- 无参数：加载模式，此后回合语音为主，直到用户说「别说话了」「关掉语音」退出
- 主动出声（用户没点名）或出声时机拿不准：先读 references/etiquette.md 再决定

## 交流模式

- 一个 `say` 只说一段话：短句合成稳、边界清晰、用户可随时打断
- 多段串联写进同一条 Bash 调用，段间用 `&&` 连接；需要循环时用 for 串行遍历，禁止并行多个含 say 的 Bash 调用
- 语言默认英文：kokoro 英文嗓表现显著优于中文嗓（全量试听结论），即使用户用中文提问，也先说英文再中文简释；用户点名要中文时改用预设 zh（matcha zh_baker）或克隆嗓
- 嗓音默认 af_maple：103 嗓试听的最佳综合表现；切嗓用 `say -v <名>`，克隆角色（frieren / dva / lucy）名字直达，`say -v '?'` 列系统嗓回退表
- 克隆嗓链路只支持放慢语速：`-r` 加速会被静默忽略并写一行 stderr，不视为故障
- 收尾中文简释：简单说明说了什么（概述立场与要点），不做逐字翻译；内容用户已掌握时（如纯情绪表达）省略

## 出声礼仪

壳内只留总原则：出声是对环境的扰动，沉默是默认态，打破沉默需要高信号事件。事件清单与判定细则读 references/etiquette.md。

## 红线与故障恢复

- 禁止并行发起多个含 say 的 Bash 调用：多个进程同时发声会叠声
- say 失败自动回退系统嗓是设计行为，不手动重试、不换引擎重跑
- say 静默失败（exit 0 但没出声）概率极低；用户反馈没听到时，先重放一次再排查
